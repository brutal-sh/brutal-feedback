# Brutal support

Start with [Brutal Help](https://brutal.sh/help/#docs) for setup, design tools, and troubleshooting. Download builds and read release notes on [Releases](https://github.com/brutal-sh/brutal-feedback/releases).

## Report a bug

1. Search [open issues](https://github.com/brutal-sh/brutal-feedback/issues) for the behavior.
2. In Brutal, choose **Help → Report an Issue**, or open the [bug form](https://github.com/brutal-sh/brutal-feedback/issues/new?template=bug.yml).
3. Include the beta release number, macOS version, Mac model, what you expected, and what happened. If it is repeatable, include steps using a blank or shareable design.
4. Review the draft and submit it on GitHub. Share screenshots or excerpts from Settings → Diagnostics only if they help explain the issue and contain information you can make public.

The app opens your browser and can prefill the app version. You decide what to share and submit. Keep private designs, file paths, prompts, account details, and credentials out of public reports.

## Privacy and usage stats

Brutal handles optional usage sharing through **Settings → Privacy**. The [privacy disclosure](https://brutal.sh/help/privacy/#what-is-sent) lists the data sent after opting in, where it goes, and how long Brutal keeps the totals. You can report issues and request help regardless of your sharing choice.

## Other feedback

Use the [feature form](https://github.com/brutal-sh/brutal-feedback/issues/new?template=feature.yml) for a concrete change. For questions and open-ended feedback, use [Discussions](https://github.com/brutal-sh/brutal-feedback/discussions). For suspected vulnerabilities, follow the [private reporting process](SECURITY.md).
